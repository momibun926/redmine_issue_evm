# Earned Value Management (EVM) Calculation Plugin

[![Rate at redmine.org](http://img.shields.io/badge/rate%20at-redmine.org-blue.svg?style=flat)](http://www.redmine.org/plugins/redmine_issue_evm)

チケットの開始日、期日、予定工数、作業時間を利用してEVM値の計算とチャートを表示する機能を提供しています。期日が入力されず、バージョンの期日がある場合は、期日としてバージョンの期日を利用します。EVMを使うと、プロジェクトの進捗と状況を把握し、今後のパフォーマンスを予測できます。

# バージョンと動作環境
* プラグインのバージョン: 7.0.0
* **Redmine 7.0 以上専用**です。

このプラグインはRedmine 7の機能(SVGアイコンなど)を利用しています。Redmine 7より前のバージョンでは動作しません。

# 主な機能
## EVM値の計算とチャート表示
* プロジェクト全体（子孫プロジェクトを含む）ESも計算します
* バージョン別
* 担当者別（日毎の予定時間を含む）
* 親チケット別
* トラッカー別
* 日毎の進捗率を基にしたEVの計算
* 日毎のEAC
* 計算対象にならなかったチケットの一覧
* 概要ページにEVM値のサマリーを表示

## 基本情報の表示
* プロジェクトの期間
* ステータス
* プロジェクト期日までの日数
* 計算対象となっているチケットの件数
* ベースラインとの差異とそのチケットのリスト
* バージョン、担当者別、トラッカー別のチケット件数
* EVM(PV,EV,AC)のチャート表示。予測のチャートはプロジェクトが完了すると表示されません。

## ベースライン
* ある時点のPVを記録しておくことが出来ます
* 作成したベースラインの詳細と履歴を参照できます

## EVMをもとにしたプロジェクトの報告
* EVM値とともにプロジェクト概況を記録できます
* 過去の概況の一覧、照会、編集

## 共通設定
* 1日の基準時間、休日・週末の除外（と休日の地域）
* ETCの計算方法
* 予測チャートの表示、パフォーマンスチャートの表示、閾値、未完了チケットの表示

# インストール
(1) ソースの取得

**ZIPファイルの場合**

* ZIPファイルをダウンロードします
* `[redmine_root]/plugins/` に `redmine_issue_evm` フォルダを作成します
* 作成したフォルダにZIPファイルを解凍します

**git cloneの場合**

```
git clone https://github.com/momibun926/redmine_issue_evm [redmine_root]/plugins/redmine_issue_evm
```

(2) gemのインストール（`[redmine_root]` で実行）

```
bundle install
```

(3) マイグレーション

```
bundle exec rake redmine:plugins:migrate NAME=redmine_issue_evm RAILS_ENV=production
```

(4) アセットのプリコンパイル（プラグインのアイコンとスタイルシート）

```
bin/rails assets:precompile RAILS_ENV=production
```

(5) Redmineを再起動します。

アイコンや画面の表示がおかしい場合は、ブラウザのキャッシュをクリアしてください（Ctrl+F5）。
プラグインを更新して、スタイルシート、スクリプト、画像が変更された場合も、(4)を実行してからRedmineを再起動してください。

# アンインストール
```
bundle exec rake redmine:plugins:migrate NAME=redmine_issue_evm VERSION=0 RAILS_ENV=production
```

その後、`[redmine_root]/plugins/` から `redmine_issue_evm` フォルダを削除して、Redmineを再起動します。

# 使い始めるには
(1) 管理 > ロールと権限 で権限を設定します。このプラグインの権限は「EVM」の欄に表示されます。

(2) プロジェクトの 設定 > モジュール で「EVM」を有効にします。

(3) プロジェクトの「EVM」タブをクリックします。初回は共通設定ページが表示されますので、設定を保存すると使い始められます。

## 権限
| 権限 | できること |
| --- | --- |
| EVMプラグインタブの表示 | EVMタブと各画面（プロジェクト、バージョン別、担当者別、親チケット別、トラッカー別、計算対象外のチケット、ベースラインとの差異）の表示。プロジェクトのメンバーのみ利用できます。 |
| ベースラインの一覧表示 | ベースラインの一覧、履歴、詳細の表示 |
| ベースラインの設定 | ベースラインの作成、編集、削除（表示を含む） |
| EVM設定の編集 | プロジェクトの共通設定の作成、編集 |
| プロジェクト報告 | プロジェクト報告の一覧、表示、作成、編集、削除 |

## 日付とタイムゾーン
* 基準日は、EVMのページを最初に開いたときに、ブラウザ（端末）の日付になります。
* プロジェクトの概要や活動など、ほかの画面の日付は、アカウントのタイムゾーン設定に従います。未設定の場合はサーバーのタイムゾーンが使われます。サーバーがUTCで動いている日本では、午前中に日付が前日で表示されることがあります。個人設定でタイムゾーンを設定してください。

# EVM値の計算について
プロジェクト(子孫プロジェクト含む)内の、以下のすべての項目に入力があるチケットを対象にして、EVM値を計算しています。

* 開始日
* 期日(未入力の場合はバージョンの期日)
* 予定工数(0でも構いませんがPV,EVが計算できないため意味がありません)

親チケットの予定工数も入力できるので、チケットの親子関係に関係なくチケット毎にPV,EVを算出しています。

* PV : 開始日、期日、予定工数を利用して、PVを計算します。日毎の工数を計算しています。
* EV : チケットをCLOSEした日に、予定工数をEVとして計算しています。進捗率が設定されている場合は、進捗率をセットした日に、予定工数に進捗率をかけて計算しています。
* AC : PVの計算に使われているチケットの作業時間を使って、ACを計算しています。

## EVM値の計算例
開始日:2015/08/01,期日:2015/08/03,予定工数:24.0時間のチケットを作成。この時点では、PVのみが有効。PVは日毎のPVから累積値を計算しています。チケットが完了していないので、EVは計算されません。

* PV -> 8/1:8.0時間 8/2:8.0時間 8/3:8.0時間　(24時間を3日で割って日毎のPVを計算)
* EV -> 0
* AC -> 0

| EVM | 8/1 | 8/2 | 8/3 |
| --- | --- | --- | --- |
| PV  | 8   | 16  | 24  |
| EV  | 0   | 0   | 0   |
| AC  | 0   | 0   | 0   |

チケットの作業時間を8/1,8/2,8/3に10.0時間、6.0時間、8.0時間入力する。日毎のPVに対して、ACの累積値が計算されます。

* PV -> 8/1:8.0時間 8/2:8.0時間 8/3:8.0時間
* EV -> 0
* AC -> 8/1:10.0時間 8/2:6.0時間 8/3:8.0時間

| EVM | 8/1 | 8/2 | 8/3 |
| --- | --- | --- | --- |
| PV  | 8   | 16  | 24  |
| EV  | 0   | 0   | 0   |
| AC  | 10  | 16  | 24  |

チケットを8/3にCLOSEする。チケットのクローズした日がEVの計上日になります。

* PV -> 8/1:8.0時間 8/2:8.0時間 8/3:8.0時間
* EV -> 8/3:24.0時間
* AC -> 8/1:10.0時間 8/2:6.0時間 8/3:8.0時間

| EVM | 8/1 | 8/2 | 8/3 |
| --- | --- | --- | --- |
| PV  | 8   | 16  | 24  |
| EV  | 0   | 0   | 24  |
| AC  | 10  | 16  | 24  |

上記のPV,EV,ACをもとに、チャート、EVM値を計算しています。

## ベースライン
ある時点のPVを記録する機能です。ベースラインを設定しておくことで、ベースライン作成以降のタスクの増加(チケットが増加)、スケジュール変更がチャート上に表示され、ベースラインからどれくらい乖離しているかが確認しやすくなります。
なお、ベースラインが設定されている場合は、ベースラインをもとにEVM値が計算されますので、注意してください。ただし、表示オプションの設定で、ベースラインを利用しないでEVM値を計算することもできます。この場合はベースライン設定後に変更・登録されたチケットも含めてEVM値が計算されます。（プロジェクトの実情に合わせて計算されることになります）
過去に設定したベースラインを参照することもできます。

## 表示オプション
EVM値の計算、チャートの表示は以下のオプションが選択可能です。

* EVM値を計算する基準日の変更
* ベースラインもしくは、すべてのチケットをもとにしたEVMの計算
* EVM値の説明を表示

## 稼働日について
1. 土日、休日は除外してPVを計算出来ます。（共通設定ページで設定してください）
2. もしチケットの期間が、週末、休日のみの場合は、すべて稼働日とします
3. 休日はholidays gemを使っています。対象となる地域は共通設定ページ（コンテキストメニューの「共通設定」リンク）で設定してください。

例)

日本では2017年は 5/3,5/4,5/5 は祝日です。チケットの期間によって以下のように計算します。

* チケットの期間に週末、祝日が含まれている場合

|開始日              |期日                |見積もり時間   |稼働日数   |1日あたりの見積もり時間|
|--------------------|--------------------|---------------|-----------|----------------------|
|May 1, 2017 (Monday)|May 8, 2017 (Monday)|12 hours       |3 days     |4 hours               |

* チケットの期間に週末、祝日が含まれている場合(期日が週末)

|開始日              |期日                |見積もり時間   |稼働日数   |1日あたりの見積もり時間|
|--------------------|--------------------|---------------|-----------|----------------------|
|May 1, 2017 (Monday)|May 7, 2017 (Sunday)|10 hours       |2 days     |5 hours               |

* チケットの期間が祝日、休日のみの場合

|開始日              |期日                |見積もり時間   |稼働日数   |1日あたりの見積もり時間|
|--------------------|--------------------|---------------|-----------|----------------------|
|May 3, 2017 (Wed)   |May 7, 2017 (Sunday)|20 hours       |5 days     |4 hours               |

# チャートの表示
計算されたEVM値を元に、以下のチャートを表示します。
チャートの表示には、Chart.jsを利用しています。Chart.bundle.min.js (Chart.js v2.8.0) と chartjs-plugin-annotation (v0.5.7) をこのプラグインに同梱しています。

**メインチャート**
計算対象のチケットからPV,EV,ACの累積値を時系列で表示します。ベースラインが設定されている場合は、ベースラインも表示します。

**パフォーマンスチャート**
PV,EV,ACが計算されている日だけ、SPI,CPI,CRを計算して表示します。プロジェクトメンバーがこまめにチケットのクローズ、作業時間のエントリーをしている場合は、プロジェクト全体のパフォーマンスの計測と予測の精度が上がります。

**バージョン別チャート**
あなたのプロジェクトがバージョンを活用しているのならば、とても役に立つチャートです。プロジェクト内の任意のバージョンを選択して、チャートを表示することが可能です。

**担当者別チャート**
プロジェクトのメンバーが多い場合にとても役に立ちます。メンバー各々のチャートを俯瞰することが出来るため、プロジェクト全体を見ているだけではわからない、メンバー一人一人のパフォーマンスを見ることが出来ます。

**親チケット別チャート**
チケットを階層構造にしてタスク管理をしている人向けです。

**トラッカー別チャート**
トラッカーを細分化して管理している人向けです。EVMの計算対象にしたくないトラッカーがある場合は、必要なトラッカーだけ選択してチャートを表示することができます。

# 開発
## 開発環境
以下の環境で開発とテストをしています。

* Redmine 7.0.2
* Ruby 4.0.0
* Rails 8.1.3
* PostgreSQL

## テスト
テストは `test/` にあります。`[redmine_root]` で実行します（Redmineのテスト用データベースを用意してください）。

```
bundle exec rake redmine:plugins:test NAME=redmine_issue_evm RAILS_ENV=test
```

## コーディングスタイル
RuboCop（RuboCop 1.72以上、rubocop-rails、rubocop-performance）でチェックしています。プラグインのフォルダで実行してください。設定は `.rubocop.yml` にあります。

```
rubocop
```
