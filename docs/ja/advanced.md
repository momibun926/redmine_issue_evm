## 1. ベースライン（計画を記録して変更を見る）

### ベースラインとは

ベースラインは、**作成した時点の各チケットの開始日・期日・予定工数のコピー** です。ベースラインを作っておくと、そのあとにチケットが増えたり、期日が延びたりしても、「最初の計画」と比べられます。

### 必要な権限

| 権限 | できること |
| --- | --- |
| ベースラインの一覧表示 | ベースラインの一覧、履歴、詳細を見る |
| ベースラインの設定 | ベースラインの作成、編集、削除 |

### 作り方

1. EVM画面の右上の **ベースラインの設定** をクリックします。
2. ベースラインの履歴の画面で **ベースラインの作成** をクリックします。BAC・開始日・期限には、今のチケットから計算した値が表示されます（変更はできません）。
3. 題名、ベースラインの基準日、説明を入れて作成します。

ベースラインの基準日は、記録用の日付です（例: 計画を承認した日）。EVMの計算には使われません。

### いつ作るか

- **計画が固まったとき**（キックオフや計画承認のあと）に1つ作ります。
- **大きな計画変更を承認したとき**（スコープの追加、リリース日の変更）に、新しいベースラインを作ります。
- 題名に日付や理由を入れておくと、履歴で区別しやすくなります（例: `2026-12-01 初版`、`2027-01-15 機能X追加後`）。

新しいベースラインを作ると、それが「最新」になり、前のベースラインは「old」になります。最新のベースラインを削除すると、残りのうち一番新しいものが「最新」に戻ります。

### ベースラインを作ると、何が変わるか

- **プロジェクトのEVM画面は、最新のベースラインのPVで計算されます**（EVとACは今のチケットから計算します）。つまり「最初の計画に対して、どれだけ進んでいるか」を表示します。
- 画面の **基本情報** に「ベースラインとの比較」が表示され、BAC・プロジェクトの期限・スケジュールが変わったかどうかが分かります。**差異の詳細を見る** から、追加されたチケット・変更されたチケット・除外になったチケットの一覧を見られます。
- EVMチャートに、ベースラインのPVの線が加わります。

今の計画で計算したいときは、**オプション > ベースラインの利用** で「ベースラインを使用しない」にチェックを入れます。過去のベースラインを選んで計算することもできます。

> バージョン別・担当者別・親チケット別・トラッカー別の内訳画面は、ベースラインを使わず、いつも今のチケットで計算します。

## 2. プロジェクト報告（定期的に状況を記録する）

### プロジェクト報告とは

その時点のEVMの値（BAC・PV・EV・AC・SV・CV）と、文章の所見をセットで記録する機能です。前回の報告との差も表示されるので、週次の定例などで「先週からどう変わったか」を説明するのに使えます。

必要な権限は **プロジェクト報告** です。

### 使い方

1. プロジェクトのEVM画面で、報告したい基準日を表示します（ふつうは今日）。
2. 右上の **プロジェクト報告** をクリックします。
3. 「前回報告したEVM」「報告する基準日のEVM」「前回報告したEVMとの差」が表示されます。報告内容には、前回の報告の文章があらかじめ入っているので、書き換えて保存します。
4. 過去の報告は **報告一覧** から見られます。

### 知っておくこと

- 報告に記録される値の単位は **日数**（時間を「一日の基準時間」で割った値）です。
- 報告には、その画面で使っていたベースラインも記録されます。
- **同じ基準日の報告を作ると、前の報告は置き換えられます**（1つの基準日に1つの報告）。
- 報告とベースラインは、Redmineの **活動** と **検索** にも表示されます。

### おすすめの書き方

報告内容に、毎回同じ見出しを使うと、前回の文章を書き換えるだけで済みます。

```
h3. 状況
SPI 0.85、CPI 0.92。実装の遅れが続いている。

h3. 原因
機能Xのレビュー待ちで2日停滞。

h3. 対策
レビュー担当を1名追加。12/20までにSPI 0.95を目指す。
```

## 3. 内訳画面（遅れの原因を絞り込む）

プロジェクト全体の値だけでは、どこが遅れているかが分かりません。EVM画面の右上のリンクから、内訳を見られます。

| 画面 | 向いている使い方 |
| --- | --- |
| バージョン別 | リリースごとの進み具合を比べる |
| 担当者別 | メンバーごとの進み具合と負荷を見る。グラフには日ごとの予定時間と「一日の基準時間」の線が出るので、予定の詰め込みすぎが分かります |
| 親チケット別 | 機能やフェーズを親チケットにまとめている場合に、まとまりごとに見る |
| トラッカー別 | 「機能」「バグ」などの種類ごとに見る。計算に含めたくないトラッカーを外して見ることもできます |

使い方は共通で、**オプション** のリストから対象を選んで（複数選択できます）**適用** をクリックします。選んだ対象ごとに、EVMの値とグラフが並びます。

## 4. 基準日の変更とCSV出力

- **基準日**: オプションの「基準日」を過去の日付にすると、その日の時点の値を表示します。振り返りや、報告をあとから作るときに使います。**クリア** で今日に戻ります。
- **EVM値の説明**: オプションで「EVM値の説明をサイドバーに表示する」にチェックを入れると、各値の意味がサイドバーに表示されます。EVMに慣れていないメンバーと画面を見るときに便利です。
- **CSV**: EVMタブの表の下の **CSV** リンクから、日ごとのPV・EV・ACの累積値を出力できます。

## 5. プロジェクトの概要ページ

共通設定を作ったプロジェクトでは、プロジェクトの **概要** ページに、今日の時点のEVMのサマリー（BAC・PV・EV・AC・SV・CV・SPI・CPI）が表示されます。ベースラインがある場合は、最新のベースラインで計算します。EVM画面を開かなくても、プロジェクトの状態をひと目で確認できます。

## 6. 共通設定を見直す

共通設定は、EVM画面の右上の **共通設定** からいつでも変更できます（権限: EVM設定の編集）。

| 項目 | 見直すタイミング |
| --- | --- |
| 一日の基準時間 | 実際の1日の作業時間が8時間と大きく違うとき（日数の表示と、担当者別の基準線が変わります） |
| 休日の除外・地域 | 海外拠点のプロジェクトなど、祝日の地域が違うとき |
| ETCの計算方法 | 予測が楽観的すぎる・悲観的すぎると感じるとき（[EVMの読み方](evm-basics.md#3-予測) を参照） |
| 閾値 | 赤やオレンジの表示が多すぎる・少なすぎるとき |

## 7. REST API（Excelや他のサービスからEVM値を使う）

EVMタブの表と同じ値（BAC・PV・EV・AC・SV・CV・SPI・CPI・CR・ETC・EAC・VAC・TCPI、ES値）を、JSON または XML で取得できます。Excelに取り込んで独自の集計表を作る、複数のプロジェクトの値を一覧にする、チャットツールに毎週通知する、といった使い方ができます。パラメータと応答の項目の一覧は、[README](../../README_ja.md#rest-api) を参照してください。

### 準備

1. 管理者が **管理 > 設定 > API** で「RESTによるWebサービスを有効にする」をオンにします。
2. 呼び出すユーザーは、対象のプロジェクトのメンバーで、「EVMプラグインタブの表示」の権限が必要です。
3. そのユーザーの **個人設定** の画面の右側で、**APIアクセスキー** を確認します（「表示」をクリック）。

ほかのサービスから定期的に呼び出す場合は、そのための専用のユーザーを作り、必要なプロジェクトだけのメンバーにしておくと、見える範囲を絞れます。

### 呼び出し方

```
https://<Redmineのアドレス>/projects/<プロジェクトの識別子>/evms.json
```

| パラメータ | 値 | 意味 |
| --- | --- | --- |
| `baseline` | `latest`（省略時） | 最新のベースラインで計算します。ベースラインがなければ、ベースラインなしで計算します。 |
| | `none` | ベースラインを使わず、今のチケットの状態で計算します。 |
| `basis_date` | `2026-11-27` の形 | 基準日。省略すると今日です。 |

APIアクセスキーは、`X-Redmine-API-Key` ヘッダーで渡します。どちらの計算か（ベースラインの名前、またはなし）は、応答の `baseline` に入ります。`hours` が時間、`days` が日数（共通設定の「一日の基準時間」で割った値）で、EVMタブの表の上段・下段と同じ値です。

### Excelから使う（Power Query）

Excel（Microsoft 365、Excel 2016 以降の Windows 版）の Power Query で取り込むと、**更新** ボタンでいつでも最新の値にできます。

1. **データ > データの取得 > その他のデータソースから > 空のクエリ** を選びます。
2. Power Query エディターで **ホーム > 詳細エディター** を開き、次の内容に置き換えます。`url`・`project`・`apiKey` は自分の環境に合わせてください。

```
let
    url = "https://redmine.example.com",
    project = "myproject",
    apiKey = "<APIアクセスキー>",
    source = Json.Document(Web.Contents(url, [
        RelativePath = "projects/" & project & "/evms.json",
        Query = [baseline = "latest"],
        Headers = [#"X-Redmine-API-Key" = apiKey]
    ])),
    evm = source[evm],
    table = Table.FromColumns(
        {Record.FieldNames(evm[hours]), Record.FieldValues(evm[hours]), Record.FieldValues(evm[days])},
        {"指標", "時間", "日数"})
in
    table
```

3. 「資格情報の指定が必要です」と表示されたら **資格情報の編集** をクリックし、**匿名** を選んで **接続** します（キーはヘッダーで渡しているため）。
4. **ホーム > 閉じて読み込む** で、シートに「指標・時間・日数」の表ができます。値を新しくするときは **データ > すべて更新** です。

- ベースラインを使わない値にするには、`baseline = "latest"` を `baseline = "none"` にします。過去の日の値にするには、`Query = [baseline = "latest", basis_date = "2026-11-01"]` のように基準日を足します。
- プロジェクトが完了していると、ETC・EAC・VAC・TCPI は空欄になります（EVMタブの「-」と同じ）。
- **注意**: APIアクセスキーはブックの中に保存されます。キーを入れたブックは他の人に渡さないでください。ブックを共有するときは、使う人がそれぞれ自分のキーに書き換えるようにします。キーが漏れたら、個人設定の画面でリセットすると古いキーは使えなくなります。

### 他のサービス・スクリプトから使う

コマンドラインで確かめるには curl が手軽です。

```
curl -H "X-Redmine-API-Key: <APIアクセスキー>" "https://redmine.example.com/projects/myproject/evms.json?baseline=none"
```

Python の例（SPIとCPIを表示する）:

```python
import requests

res = requests.get(
    "https://redmine.example.com/projects/myproject/evms.json",
    params={"baseline": "latest"},
    headers={"X-Redmine-API-Key": "<APIアクセスキー>"},
    timeout=30,
)
res.raise_for_status()
evm = res.json()["evm"]
print(evm["basis_date"], "SPI", evm["hours"]["spi"], "CPI", evm["hours"]["cpi"])
```

使い方の例:

- **定期的な記録・通知**: 毎週決まった曜日に呼び出して、SPI・CPI をスプレッドシートに追記したり、チャットに通知したりします。[プロジェクト報告](#2-プロジェクト報告定期的に状況を記録する) と違って、Redmine の画面を開かずに記録できます。
- **複数プロジェクトの一覧**: プロジェクトの識別子を変えて順に呼び出し、プロジェクトごとの SPI・CPI を1つの表にまとめます。
- **しきい値でのアラート**: SPI や CPI が共通設定の閾値を下回ったら通知する、といった判定を外部で行います。

### うまくいかないとき

| 状態 | 原因と対処 |
| --- | --- |
| 403 Forbidden | REST API が無効、ユーザーがプロジェクトのメンバーでない・権限がない、またはプロジェクトでEVMのモジュールが有効になっていない |
| 401 Unauthorized | APIアクセスキーが違う、または渡されていない |
| 404 Not Found | プロジェクトの識別子が違う |
| 422 と `errors` | `baseline` が `latest`・`none` 以外、`basis_date` が日付でない、またはプロジェクトに共通設定がない（メッセージを確認） |
| `no_data` が `true` | 計算の対象になるチケット（開始日・期日・予定工数があるもの）がない |
