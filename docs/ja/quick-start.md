# 最小構成で始める

ベースラインもプロジェクト報告も使わず、**「チケットに計画を入れて、作業時間を記録して、EVM画面を見る」だけ** で運用する方法です。まずはこの形で始めて、慣れてから [一歩進んだ運用](advanced.md) に進むことをおすすめします。

[目次に戻る](index.md)

## 1. 準備（管理者が1回だけ行う）

### 1-1. プラグインをインストールする

[README](../../README_ja.md) の「インストール」の手順で入れます。`assets:precompile` を忘れると、画面のスタイルが崩れます。

### 1-2. ロールに権限を付ける

**管理 > ロールと権限** で、EVMを見せたいロール（例: 管理者、開発者）に、「EVM」の欄の権限を付けます。最小構成で必要なのは次の2つです。

| 権限 | 誰に付けるか |
| --- | --- |
| EVMプラグインタブの表示 | EVMを見る人全員 |
| EVM設定の編集 | 共通設定を作る人（プロジェクトの管理者など） |

「EVMプラグインタブの表示」は、プロジェクトのメンバーだけが使えます。

### 1-3. Redmineの設定を確認する

EVMはRedmineの標準の項目から計算するので、次が使える状態になっている必要があります。

- プロジェクトの **設定 > モジュール** で「チケットトラッキング」と「時間管理」が有効
- 使うトラッカーで、標準フィールドの **開始日・期日・予定工数** が有効（**管理 > トラッカー** で確認）
- **管理 > 設定 > チケットトラッキング** の「親チケットの値の算出方法」で、開始日 / 期日と進捗率が「子チケットの値から算出」（Redmineの初期値）

## 2. プロジェクトでEVMを有効にする

1. プロジェクトの **設定 > モジュール** で「EVM」にチェックを入れて保存します。
2. プロジェクトのメニューに **EVM** タブが出るので、クリックします。
3. 初回は「EVM共通設定の作成」画面が開きます。最小構成では、次のように入れれば十分です。

| 項目 | おすすめの値 | 意味 |
| --- | --- | --- |
| 一日の基準時間 | `8.0` | 1日あたりの作業時間。時間を日数に換算するときに使います |
| 日数の計算はRedmineの休業日と祝日（holidays gemに従う）を除外する | チェックを入れる | Redmineの休業日と祝日（holidays gemに従う）を作業日から外してPVを計算します |
| 休日の設定 | `jp`（日本の場合） | 祝日の地域 |
| ETCの計算方法 | 普通 | 残作業の見積もり方。迷ったら「普通」 |
| 予測値の表示 | チェックを入れる | グラフに完了までの予測線を出します |
| パフォーマンスチャートの表示 | チェックを入れる | SPI・CPIの推移のグラフを出します |
| SPI・CPI・CRの閾値 | `0.9` | これ以下の値を赤で表示します（0より大きく0.99以下） |
| 未完了チケットの表示 | チェックを入れる | 期日を過ぎても終わっていないチケットの一覧を出します |

4. 保存すると、EVMの画面が表示されます。

## 3. チケットの入れ方（メンバー全員のルール）

最小構成で守るルールは **3つだけ** です。

1. **チケットを作ったら、開始日・期日・予定工数を入れる**
   - 開始日と期日がないチケットは、EVMの計算から外れます（期日がなくても、対象バージョンに期日があれば、その期日が使われます）。
   - 予定工数が空のチケットは計算に入りますが、0時間として扱われるので、PVとEVに何も加わりません。
2. **作業したら、そのチケットに作業時間を記録する**
   - ACは、計算対象のチケットに記録された作業時間だけを集計します。チケットに紐付かない作業時間や、計算から外れたチケットの作業時間は入りません。
3. **終わったら、チケットを完了のステータス（終了扱いのステータス）にする**
   - チケットを終了にした日に、予定工数の全部がEVになります。
   - 途中の進捗も反映したいときは、進捗率を更新します。進捗率を変更した日に「予定工数 × 進捗率」がEVになります。

> **親子チケットを使う場合**: 予定工数は子チケット（末端のチケット）にだけ入れ、親チケットの予定工数は空にしておくのがシンプルです。このプラグインはチケットごとにPVを計算するため、親にも子の合計を入れると二重に数えられます。

## 4. 画面の見方（週に1回、これだけ見る）

EVMタブを開くと、今日の時点の値が表示されます。最初に見るのは次の4つです。

| 見るところ | 見方 |
| --- | --- |
| **SPI**（EVMタブの表） | 1より小さいと予定より遅れています。閾値以下は赤で表示されます |
| **CPI**（EVMタブの表） | 1より小さいと予定より作業時間がかかっています |
| **基本情報 > ステータス** | 「プロジェクト期間内です」「期日を過ぎています」など、全体の状態 |
| **未完了チケット** タブ | 期日を過ぎても終わっていないチケット。遅れの原因を探す入口です |

あわせて、ときどき **EVMの計算から除外されているチケット**（画面右上のリンク）も確認してください。開始日や期日の入れ忘れがここに出ます。

表の上段は時間、下段は「一日の基準時間」で割った日数です。

## 5. 計算例

3人で1週間（2026年12月7日〜11日、月〜金）の作業をする例です。

| チケット | 開始日 | 期日 | 予定工数 | 1日あたりのPV |
| --- | --- | --- | --- | --- |
| A 設計 | 12/7 | 12/8 | 16時間 | 8時間 |
| B 実装 | 12/9 | 12/11 | 24時間 | 8時間 |
| C テスト準備 | 12/7 | 12/11 | 10時間 | 2時間 |

BAC（予定工数の合計）は 50時間です。

12月9日の終わりの時点で、次の状態だったとします。

- A は 12/8 に終了。作業時間は 12/7 に10時間、12/8 に8時間
- C は 12/9 に進捗率を50%に更新。作業時間は 12/7〜12/9 に毎日2時間
- B は 12/9 に着手して4時間作業。進捗率は0%のまま

基準日を 12/9 にしたときの値は次のとおりです。

| 値 | 計算 | 結果 |
| --- | --- | --- |
| PV | A 16 + B 8 + C 6 | 30時間 |
| EV | A 16 + C 10×50% | 21時間 |
| AC | A 18 + B 4 + C 6 | 28時間 |
| SV | EV − PV | −9時間（遅れ） |
| CV | EV − AC | −7時間（超過） |
| SPI | EV ÷ PV | 0.70 |
| CPI | EV ÷ AC | 0.75 |
| ETC（普通） | (BAC − EV) ÷ CPI | 約38.7時間 |
| EAC | AC + ETC | 約66.7時間 |

SPIもCPIも閾値の0.9以下なので、赤で表示されます。「予定より遅れていて、しかも作業時間が多くかかっている。このままだと全体で約67時間かかる見込み」と読めます。
