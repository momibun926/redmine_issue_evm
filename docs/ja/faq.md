# よくある質問とトラブルシューティング

[目次に戻る](index.md)

## 画面が表示されない

### プロジェクトにEVMタブが出ない

次の3つを確認してください。

1. プロジェクトの **設定 > モジュール** で「EVM」が有効になっているか
2. 自分のロールに **EVMプラグインタブの表示** の権限があるか（**管理 > ロールと権限**）
3. そのプロジェクトのメンバーになっているか（この権限はメンバーだけが使えます）

### EVMタブを開くと「403」になる

そのプロジェクトで共通設定がまだ作られておらず、自分に **EVM設定の編集** の権限がない場合に起こります。EVMタブを最初に開くと共通設定の作成画面に移動するためです。権限のある人に、一度EVMタブを開いて共通設定を保存してもらってください。

### 画面のレイアウトが崩れる、タブがラジオボタンのまま表示される

プラグインのスタイルシートが読み込まれていません。Redmineのフォルダで次を実行してから、Redmineを再起動してください。プラグインを更新したときも必要です。

```
bin/rails assets:precompile RAILS_ENV=production
```

それでも直らないときは、ブラウザのキャッシュを消して再読み込みしてください（Ctrl+F5）。

### 「表示するデータがありません」と表示される

計算の対象になるチケットが1件もありません。開始日と期日（または期日のある対象バージョン）が入ったチケットを作ってください。

## 値がおかしい

### 作ったはずのチケットが計算に入っていない

**EVMの計算から除外されているチケット** の一覧を見てください。開始日がない、または期日も対象バージョンの期日もないチケットが表示されます。

トラッカーの設定で開始日や期日のフィールドが無効になっていると、そもそも入力できません。**管理 > トラッカー** の標準フィールドを確認してください。

### ACが実際の作業時間より少ない

ACには、**計算対象のチケットに記録された作業時間だけ** が入ります。次の作業時間は入りません。

- チケットを指定せず、プロジェクトに直接記録した作業時間
- 計算から除外されているチケット（開始日・期日がないチケット）の作業時間

### CPIが0になる、ETCが0になる

作業時間が記録されていない（ACが0）と、CPIは0になり、ETCも0になります。作業時間を記録すると計算されます。EVが0の場合も、SPIとCPIは0になります。

### 進捗率を入れたのに、EVが増えない

EVは、**進捗率を変更した日** に計上されます。チケットを作成するときに最初から進捗率を入れた場合は、変更の記録（履歴）がないため、EVに入りません。チケットを作成したあとで進捗率を更新するか、チケットを終了にしてください。終了にした日に、予定工数の全部がEVになります。

### 予定工数を入れたのに、BACが思ったより大きい

親チケットと子チケットの両方に予定工数を入れていないか確認してください。このプラグインはチケットごとに計算するので、親に子の合計を入れると二重に数えられます。予定工数は子チケットにだけ入れるのがおすすめです。

### 土日や祝日もPVに入っている

**共通設定** で「日数の計算は休日および祝日を除外する」にチェックが入っているか、「休日の設定」が正しい地域（日本なら `jp`）になっているかを確認してください。

なお、チケットの期間がすべて土日・祝日の場合は、除外せずにその期間の全日を作業日として計算します。

### 日付が1日ずれる

プロジェクトの概要や活動などの日付は、アカウントのタイムゾーン設定に従います。未設定だとサーバーのタイムゾーン（多くはUTC）になるため、日本では午前中に前日の日付になることがあります。**個人設定** でタイムゾーンを設定してください。

EVM画面の基準日は、最初に開いたときにブラウザ（端末）の日付になります。

### 概要ページの値とEVM画面の値が違う

概要ページのサマリーは、いつも **今日の日付** と **最新のベースライン** で計算します。EVM画面で基準日を変えていたり、別のベースラインや「ベースラインを使用しない」を選んでいたりすると、値が違います。

### ベースラインを作ったら、値が変わった

ベースラインがあると、プロジェクトのEVM画面は **最新のベースラインのPV** で計算します。ベースラインのあとに追加したチケットは、PVに入りません。今の計画で計算したいときは、オプションの「ベースラインを使用しない」にチェックを入れてください。詳しくは [一歩進んだ運用](advanced.md#1-ベースライン計画を記録して変更を見る) を参照してください。

## 運用について

### 最初はどの機能を使えばいいか

[最小構成で始める](quick-start.md) の運用（チケットに開始日・期日・予定工数を入れ、作業時間を記録し、終わったら終了にする）だけで十分です。ベースラインやプロジェクト報告は、計画の変更を管理したくなったとき、定期的な報告が必要になったときに足してください。

### チケットはどのくらいの大きさに分けるといいか

EVは、チケットを終了にした日（または進捗率を更新した日）に計上されます。大きなチケットだと、終わるまでEVが増えず、遅れているように見えます。1〜3日程度で終わる大きさに分けると、グラフが実態に近づきます。

### プロジェクト報告が消えた

同じ基準日の報告を作ると、前の報告は新しい報告に置き換えられます。1つの基準日に残る報告は1つです。

### 子プロジェクトのチケットも計算に入るか

入ります。プロジェクトのEVMは、子孫プロジェクトのチケットも含めて計算します。

### 過去のベースラインで計算したい

EVM画面の **オプション > ベースラインの利用** で、使いたいベースラインを選んで **適用** をクリックします。

### プロジェクトを削除すると、EVMのデータはどうなるか

共通設定・ベースライン・プロジェクト報告も一緒に削除されます（子プロジェクトの分も含みます）。アーカイブしたときは、何も削除されません。

このプラグインの古いバージョンでは、プロジェクトを削除してもEVMのデータが残っていました。残っている件数は、Redmineのフォルダで次のコマンドを実行すると確認できます。

```
bundle exec rake redmine_issue_evm:orphans:count RAILS_ENV=production
```

削除するときは、次のコマンドを実行します。元には戻せないので、先にデータベースのバックアップを取ってください。

```
bundle exec rake redmine_issue_evm:orphans:delete RAILS_ENV=production
```
